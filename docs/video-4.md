### 1. Temperature Parameter & Prompt Basics
* **Temperature Parameter Rectification**: Controls output determinism versus randomness in LLMs.
  * Setting `temperature = 0` ensures deterministic outputs, producing identical responses for repeated identical inputs.
  * Setting `temperature = 1.5` or higher produces diverse and creative outputs for identical inputs.
* **Definition of Prompts**: Prompts are the input messages sent to language models to steer their generation.
* **Multimodal vs Text Prompts**: While multimodal prompts (text, image, audio, video) exist, text-based prompts represent the vast majority of current implementations.

---

### 2. Static vs. Dynamic Prompts
* **Static Prompts**: Queries where the entire text is provided directly by the user or hardcoded by the developer.
  * **Drawbacks**: Gives users unguided control, leading to inconsistent user experience, typos, improper formatting, and potential model hallucinations.
* **Dynamic Prompts**: Pre-designed prompt templates containing key-value placeholders that are dynamically populated with user inputs at runtime.
  * **Advantages**: Ensures consistent outputs, structured responses, and prevents user input errors.

---

### 3. Prompt Templates (`PromptTemplate`)
* **`PromptTemplate` Class**: LangChain class used to create dynamic prompts by defining template strings and input variables.
* **3 Reasons to Use `PromptTemplate` over Python f-strings**:
  1. **Built-in Validation**: Includes template validation (`validate_template=True`) to flag missing or unexpected variables during development.
  2. **Serialization & Reusability**: Allows saving templates to JSON files (`template.save('template.json')`) and reloading them (`load_prompt('template.json')`) across project files.
  3. **Ecosystem Integration**: Integrates directly into LangChain pipelines/chains (`template | model`), running seamless single-call executions (`chain.invoke()`).

---

### 4. LangChain Message Types
* **Stateless LLMs & Chat History**: LLMs do not retain context between calls; maintaining conversation flow requires appending prior exchanges to a chat history list.
* **The 3 Core Message Types**:
  * **`SystemMessage`**: Sets high-level instructions, persona, or constraints at the start of a session.
  * **`HumanMessage`**: Represents messages sent by the human user.
  * **`AIMessage`**: Represents responses generated by the AI model.
* **Role Labeling**: Explicit message objects ensure the LLM clearly distinguishes user inputs from its own past outputs.

---

### 5. `ChatPromptTemplate` & `MessagesPlaceholder`
* **`ChatPromptTemplate`**: Used in multi-turn conversations to dynamically populate variables across structured message lists.
  * Supports tuple syntax such as `[("system", "template_str"), ("human", "template_str")]` to define roles dynamically.
* **`MessagesPlaceholder`**: A specialized placeholder inside `ChatPromptTemplate` used to dynamically insert an entire list of past conversation history into a prompt at runtime.

---

### 6. Summary Comparison Table

| Concept | Class / Parameter | Primary Purpose | Key Advantage |
| :--- | :--- | :--- | :--- |
| **Single-turn Template** | `PromptTemplate` | Format single string prompts with placeholders | Validation, JSON serialization, and chain integration |
| **Multi-turn Template** | `ChatPromptTemplate` | Format structured message lists with placeholders | Handles role-based dynamic messages |
| **History Injection** | `MessagesPlaceholder` | Slot past conversation history into prompt chains | Dynamically inserts full message lists at runtime |
| **Role Messaging** | `SystemMessage` / `HumanMessage` / `AIMessage` | Label roles in conversational history | Maintains clear context ownership for stateless LLMs |
